# План работ

Два режима: двое суток и две недели. Берите тот, что подходит, и правьте даты.

## Спринт 48 часов

| Часы | Что | Признак, что этап закрыт |
|---|---|---|
| 0–2 | Разбор ТЗ и датасета, `docs/00-разбор-ТЗ.md` | Понятно, что сдаём и по каким метрикам судят |
| 2–4 | Датасет грузится в заготовку, виден на экране | Отчёт о качестве показывает распознанные колонки |
| 4–10 | Предметная логика: минимальный полезный расчёт | Есть результат, который можно показать |
| 10–16 | Ассистент отвечает по своим данным, подсказки переписаны | Ответ со ссылками на источники |
| 16–24 | Второй экран решения, выгрузка документа | Файл скачивается и открывается |
| 24–32 | Метрика «было / стало», журнал, чистка | Цифры на «Обзоре» не выдуманные |
| 32–40 | Прогон демо на чистой машине, README | `docker compose up` работает с нуля |
| 40–46 | Презентация и видео | Уложились в регламент по времени |
| 46–48 | Запас | Сдано не в последнюю минуту |

## Две недели

| Дни | Что |
|---|---|
| 1 | ТЗ и датасеты: забрать, разобрать, записать разбор. Вопросы организатору. Кода нет |
| 2–3 | Приём данных, нормализация, экран данных. Первый видимый результат |
| 4–6 | Ядро решения: главный алгоритм или модель |
| 7–8 | Второй контур: проверки, ограничения, качество результата |
| 9–10 | Ассистент и документы под свою предметную область |
| 11 | Метрика «было / стало», журнал, состояние контура |
| 12 | Прогон на чистой машине, README, границы применимости |
| 13 | Презентация по шаблону организатора, видео демонстрации |
| 14 | Запас и сдача с полем по времени |

Правило: последние три дня — упаковка, а не разработка. Если к этому моменту
ядро не работает, режется функциональность, но не упаковка: недоупакованное
решение эксперт просто не увидит.
