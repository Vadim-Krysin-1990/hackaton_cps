# Инструкции для Claude Code

Это заготовка для хакатонов по ИИ. Репозиторий копируется под каждую новую
задачу, предметная логика дописывается сверху.

## Первое, что нужно сделать в новой задаче

1. Прочитать `docs/01-постановка.md` — он заполняется под конкретный хакатон.
   Если пустой, попросить постановку у пользователя, а не выдумывать.
2. Разобрать ТЗ и датасет заказчика, записать разбор в `docs/00-разбор-ТЗ.md`.
   **Не писать код, пока датасет не разобран** — на прошлых хакатонах это была
   главная потеря времени.
3. Переписать `ROLE_HINTS` в `backend/app/ingest/loader.py` под колонки
   реального датасета и убедиться, что файл загружается.

## Среда

* Сервер: 1 ядро, 3,8 ГБ RAM, CPU only. Тяжёлое — под `nice`/`ionice`.
  **Код выхода 137 — это OOM**, а не ошибка в коде.
* Docker может быть не установлен; проверять перед тем, как советовать
  `docker compose`.
* Никакого обучения моделей. Только инференс (Ollama или облачный API),
  алгоритмика и данные.
* Виртуальное окружение и временные файлы — в каталоге scratchpad, не в репозиторий.

## Правила работы с этим кодом

* **Контур обязан работать без внешних сервисов.** Нет модели — ассистент
  отвечает фактами; нет Keycloak — работает локальный вход; нет
  sentence-transformers — работает hash-фоллбэк. Не ломать эти запасные пути:
  на защите они спасают.
* Настройки — только через `backend/app/config.py` и env с префиксом `APP_`.
  Не хардкодить адреса, пароли, названия и пороги.
* Каждое заметное действие пользователя писать в журнал через `audit(...)`,
  длительные операции оборачивать в `timed()` — на этом стоит метрика
  «было / стало», а она почти всегда и есть главный аргумент на защите.
* Русский интерфейс и русские комментарии. Сообщения об ошибках — человеческие,
  с указанием, что именно делать.
* Предметную логику класть в `backend/app/domain/`, не размазывать по каркасу.
* Перед коммитом: `cd backend && python -m pytest tests -q` и
  `cd frontend && npm run build`.

## Чего не делать

* Не коммитить датасеты и документы заказчика: на большинстве хакатонов
  материалы ТЗ конфиденциальны (например, ЛЦТ, п. 7.3.5). `.gitignore` уже
  настроен, не ослаблять его.
* Не тянуть torch и тяжёлые модели без явной просьбы — 1,5 ГБ на машине
  с 3,8 ГБ памяти.
* Не переписывать дизайн-систему (`frontend/src/index.css`): токены, типографика
  и палитра графиков проверены. Менять бренд — через `.env`.
* Не оставлять упаковку (README, презентация, видео) на последний день.

## Полезные команды

```bash
python backend/scripts/make_demo_data.py data/samples/demo.xlsx --rows 500
cd backend && python -m pytest tests -q
cd frontend && npm run build
curl -s localhost:8000/api/health        # состояние контура и модели
curl -s localhost:8000/api/metrics       # измеренное «было / стало»
```
