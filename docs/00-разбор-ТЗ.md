# Разбор ТЗ и датасета

## 1. Что требуют

* Задача: по тексту exit-интервью (свободный диалог, 500–1500 символов, русский) за минуту
  выдать JSON-паспорт: истинная причина ухода, системные боли с частотой упоминаний,
  что работает хорошо с цитатами-якорями, уровень риска для оставшейся команды,
  не менее трёх реалистичных гипотез по решению главной проблемы.
* Итоговый продукт: воспроизводимый сервис с минималистичным Web UI, загрузка .txt → результат.
* Метрики приёмки: глубина парсинга (эмоции и факты, «говорят» и «чувствуют»),
  качество инсайта, скорость меньше минуты, масштабируемость (БД, промпты без кода), фишка.
* Сдаётся: репозиторий с README, презентация 5 слайдов, видео-демо до 3 минут.
  На финале дают скрытый транскрипт.

## 2. Данные

| Что смотрим | Ответ |
|---|---|
| Формат файлов | .txt, свободный диалог; реплики могут быть с префиксами или без |
| Объём | 10–15 транскриптов по 500–1500 символов от организаторов; пока синтетика |
| Кодировка | ожидаем UTF-8, читаем с запасом cp1251 |
| Ключевое поле | имя файла; сотрудник анонимен |
| Даты | в тексте нет; дата = момент загрузки |
| Чего нет | подразделения, стажа, должности; поля в паспорте опциональны |

## 3. Ограничения

* Коммерческие API (ChatGPT, Claude) запрещены в боевом контуре. Демо на локальной
  модели через Ollama; внешний OpenAI-совместимый провайдер только как переключатель в `.env`.
* Материалы организаторов не выносить наружу. Репозиторий приватный.
* Демо локальное, без зависимости от сети.

## 4. Вопросы организатору

1. Сколько минут интервьюер тратит на разбор одной беседы сейчас? Рабочая гипотеза 40 минут.
2. Датасет на финале: тот же формат диалога?
3. Нужна ли привязка к подразделению для дашборда?

## 5. Выводы

* Из заготовки как есть: вход, журнал, метрики, LLM-клиент, DOCX, дизайн-система, графики.
* Переписывается: экран «Данные» → «Интервью», экран «Загрузка» под .txt, «Обзор» → дашборд.
* С нуля: конвейер анализа, проверка цитат, настроение по репликам, агрегация и граф связей.
* Главный риск: качество JSON от локальной модели. Ответ: жёсткая схема, повтор запроса
  при невалидном JSON, запасной путь без модели.
