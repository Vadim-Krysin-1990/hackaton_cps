# Сверка с ТЗ кейса «Экзит-интервью» и критериями хакатона

Статус: ✅ сделано и проверено · ⚠️ сделано частично или с оговоркой · ❌ не сделано.

## 1. Миссия и вход

| Пункт ТЗ | Статус | Где и как |
|---|---|---|
| Прототип HR-аналитика, который за 1 минуту превращает сырой текст беседы в паспорт проблемы | ✅ | 5–10 с на паспорт (gpt-oss:20b), 3–4 с (gpt-oss:120b); время пишется в журнал и на дашборд |
| Вход: 10–15 анонимизированных транскриптов, 500–1500 символов, свободный диалог | ✅ | Загрузка нескольких .txt за раз; три формата разбора: подписи реплик, диалог с «…», монолог с тире (10 кейсов организаторов) |
| Датасет выдаётся организаторами | ⚠️ | Пока 12 синтетических + 10 кейсов из чата организаторов; финальный датасет грузится тем же экраном |

## 2. Выход: JSON-объект с полями

| Поле ТЗ | Статус | Как реализовано |
|---|---|---|
| `exit_reason` — истинная причина (деньги, карьера, микроклимат, нереализованность) | ✅ | Ровно эти четыре категории плюс «другое»; подтверждается дословной цитатой `exit_reason_quote` |
| `pain_points` — список системных проблем с частотой упоминаний | ✅ | Категория, название, `mentions`, цитаты; частота не ниже числа подтверждённых цитат |
| `best_practices` — что работает хорошо, с цитатами-якорями | ✅ | Каждая практика с цитатой; цитата проверяется по источнику |
| `risk_zone` — уровень риска для оставшейся команды High/Medium/Low | ✅ | Плюс `risk_rationale`; правило High, если «уйдут и другие» или токсичная среда |
| `improvement_suggestions` — не менее 3 гипотез по топ-1 проблеме | ✅ | Минимум три гарантирует конвейер: если модель дала меньше, добавляются типовые с пометкой в заметках |
| JSON доступен для дашборда | ✅ | `GET /api/interviews/{id}` отдаёт паспорт как JSON; дашборд и граф считаются из него |

Сверх ТЗ: `says` / `feels` (что говорит и что чувствует), `department`, `manager`, `summary`, график настроения по репликам, отчёт проверки цитат.

## 3. Технические ограничения

| Пункт ТЗ | Статус | Как |
|---|---|---|
| Воспроизводимость: запуск на новом файле без переобучения | ✅ | Любой .txt или вставленный текст; скрытый кейс жюри грузится тем же путём |
| Интерфейс минималистичный: Web UI с загрузкой .txt и выдачей результата | ✅ | Экран «Загрузка» → карточка паспорта сразу после разбора |
| Запрещены коммерческие API (ChatGPT/Claude) в боевом контуре; open-source LLM локально или через VPN | ✅ | Только открытые модели через Ollama (gpt-oss, gemma); для разработки облако Ollama, для контура та же модель локально, переключение в `.env` |

## 4. Критерии оценки

| Критерий | Вес | Статус | Чем закрыт |
|---|---|---|---|
| Глубина парсинга: эмоциональные и фактические маркеры, «говорят» и «чувствуют» | 30% | ✅ | Поля `says`/`feels`; словарь настроения по каждой реплике с маркерами; доля «переживаний» в реплике (`feeling`); график хода разговора |
| Качество инсайта: сжатая аналитика, реалистичные гипотезы | 25% | ✅ | Гипотезы «выполнимые за квартал» в промпте; вывод ИИ по всем интервью с ответственным и измеримым эффектом; фильтр по проблеме |
| UX/UI и скорость: < 1 минуты, понятный вывод без воды | 15% | ✅ | 5–10 с; карточка: причина, боли, практики, риск, гипотезы, текст с подсветкой |
| Архитектура: масштабирование, БД, промпты без кода | 15% | ✅ | SQLite/PostgreSQL через `.env`, промпты в `prompts/*.txt` читаются при каждом запуске, переключатель моделей, Docker |
| Креативность: фишка (сентимент по динамике, визуализация связей) | 15% | ✅ | Оба названных примера: график настроения по репликам и лист «Связи» (интервью–отдел–руководитель–причина–проблема); плюс проверка цитат и сравнение моделей |

## 5. Антипаттерны

| Антипаттерн | Статус | Как избегаем |
|---|---|---|
| Красивый дашборд без логики | ✅ | Все цифры считаются из паспортов; каждая боль кликается до цитаты в тексте |
| «Средняя температура по больнице» | ✅ | Частота проблем по интервью, сгущения по отделам и руководителям, граф связей |
| Галлюцинации: несуществующие проблемы | ✅ | Проверка каждой цитаты по источнику (точно или схожесть ≥ 0,82); отклонённые показываются отдельно и в паспорт не попадают |

## 6. Рекомендуемый стек

| Пункт | Статус | Примечание |
|---|---|---|
| Python, FastAPI/Flask + LangChain или RAG-фреймворк | ⚠️ | FastAPI есть; LangChain не используется намеренно: один вызов модели с JSON-схемой проще и прозрачнее, конвейер свой |
| Лемматизация (pymorphy2) + zero-shot классификация | ⚠️ | Словарные методы по основам слов без pymorphy2; классификацию делает LLM по фиксированным категориям |
| Хранение: SQLite для кэша результатов | ✅ | SQLite по умолчанию, паспорта и выводы ИИ кэшируются |

## Открытые вопросы к организаторам

1. Норматив ручного разбора одной беседы (в сервисе 40 минут, гипотеза).
2. Будут ли в датасете названы отделы и руководители: без них лист «Связи» строится только по причинам и проблемам.
3. Регламент: 5 слайдов строго или структура свободная.
