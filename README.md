# Паспорт ухода

Сервис для HR: транскрипт exit-интервью → структурированный паспорт проблемы → дашборд
системных проблем для руководства. Каждый факт в паспорте подтверждён цитатой, которую
сервис нашёл в исходном тексте программно. Не нашёл — факт в паспорт не попадает.

Сделано на Первом ИИ-хакатоне Газпром ЦПС, 18.09.2026, кейс 4 «Экзит-интервью».

## Быстрый старт

```bash
cp .env.example .env            # впишите ключ модели или адрес локальной Ollama
docker compose up -d --build    # интерфейс на http://localhost/
```

Без Docker:

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r backend/requirements.txt
cd frontend && npm install && npm run build && cd ..
APP_SECRET_KEY=dev uvicorn app.main:app --app-dir backend --port 8000
```

Вход: `ana` / `demo2026` (роли `ruk`, `exp`, `ana`).
Демонстрационные транскрипты: `data/samples/transcripts/*.txt` (синтетика, реальных бесед нет).

```bash
python backend/scripts/make_demo_transcripts.py data/samples/transcripts --count 12
```

## Модель

Любая модель через Ollama (локально или облако) либо OpenAI-совместимый API. Выбор в `.env`:

| Переменная | Что |
|---|---|
| `APP_LLM_BASE_URL` | `http://localhost:11434` для локальной Ollama, `https://ollama.com` для облака |
| `APP_LLM_MODEL` | модель по умолчанию, например `gpt-oss:20b` |
| `APP_LLM_API_KEY` | ключ для облака или внешнего API |
| `APP_LLM_MODELS` | список моделей для переключателя в интерфейсе |

Модель недоступна — сервис не падает: паспорт строится по ключевым словам с пометкой
«fallback» в поле «движок». В интерфейсе можно прогнать одно и то же интервью разными
моделями и сравнить: на малой модели (20B) паспорт собирается за 6–12 секунд.

## Как это работает

```
транскрипт .txt
   │
   ├─ 1. parse      реплики, кто говорит (подписи, тире, сплошной текст)
   ├─ 2. sentiment  настроение по репликам: словарь, без модели, мгновенно
   ├─ 3. extract    паспорт по жёсткой JSON-схеме: модель (format=json, повтор при ошибке)
   │                или запасной путь по ключевым словам
   ├─ 4. verify     каждая цитата ищется в источнике (точно или по схожести ≥ 0,82);
   │                не найденные отклоняются и показываются отдельно
   └─ 5. done       паспорт в базе → карточка, DOCX, дашборд
```

Паспорт: `exit_reason`, `pain_points` (с частотой и цитатами), `best_practices` (с цитатами),
`risk_zone` High/Medium/Low, `improvement_suggestions` (не менее трёх), плюс `says` / `feels`.

Промпты лежат в `prompts/*.txt` и читаются при каждом анализе: HR правит текст файла,
следующий анализ идёт по новым правилам, перезапуск не нужен.

## Экраны

* **Дашборд**: причины ухода, в скольких интервью названа каждая проблема, зоны риска,
  граф связей между проблемами, что делать с главной, «было / стало».
* **Интервью**: список паспортов, карточка с подсветкой цитат в оригинале, график
  настроения по репликам, отклонённые проверкой цитаты, выгрузка DOCX, повторный анализ
  другой моделью.
* **Загрузка**: один или несколько .txt за раз либо вставленный текст, выбор модели.
* **Журнал**: кто, когда, что загрузил, сколько заняло. На нём считается метрика.
* **О сервисе**: состояние контура.

## Структура

```
backend/app/domain/exit_interview/   предметный модуль: parsing, sentiment, fallback, verify, pipeline
backend/app/api/routes_interviews.py  API: загрузка, список, карточка, дашборд, DOCX, повторный анализ
backend/app/llm/client.py             Ollama / OpenAI-совместимый клиент, JSON-режим, переключение модели
prompts/                              промпты, правятся без пересборки
frontend/src/pages/                   Dashboard, Interviews, Transcripts, Journal, About
frontend/src/components/exitcharts.tsx график настроения и граф связей
docs/                                 постановка, разбор ТЗ, заметки о процессе
```

Тесты: `cd backend && python -m pytest tests -q` (21 тест, модель в тестах недоступна намеренно).

## Безопасность и контур

* Данные не покидают контур при локальной Ollama; облако — только для разработки.
* Транскрипты анонимны, персональные данные в паспорт не переносятся.
* Каждое действие в журнале с длительностью; вход и роли есть, SSO через Keycloak
  подключается конфигурацией (`docker-compose.keycloak.yml`).
* Лимиты на размер текста и расширения файлов, ошибки без трейсбеков.

## Единый вход через Keycloak

Keycloak живёт на отдельном сервере, приложению нужен только адрес realm. Развёртывание
с машины, у которой есть SSH на сервер:

```bash
bash deploy/keycloak/push-remote.sh root@<адрес сервера> 2222
```

Скрипт ставит Docker, если его нет, поднимает Keycloak 26 с готовым realm `hackathon`
(клиент `app`, роли `app-leader`, `app-expert`, `app-analyst`, пользователи `ruk`, `exp`, `ana`)
и открывает порт 8080. В `.env` приложения: `APP_OIDC_ENABLED=true`,
`APP_OIDC_ISSUER=http://<адрес сервера>:8080/realms/hackathon`. Локальный вход остаётся
запасным путём. Для боевого контура: режим `start` с TLS вместо `start-dev`.

## Эффект

Норматив ручного разбора одной беседы задаётся `APP_BASELINE_MANUAL_MINUTES` (по умолчанию 40).
Сервис измеряет своё время в журнале и показывает формулу на дашборде:
(норматив − время сервиса) × число интервью. Главное не минуты, а лаг: системная
проблема видна в день загрузки, а не через квартал.
